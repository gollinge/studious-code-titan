# Module 11 — Building Bigger Projects

Module Type:
Advanced Beginner Project Architecture Module

Primary Goal:
Teach learners how to structure, organize, expand, and manage larger programs without becoming overwhelmed.

Educational Purpose:
This module introduces the idea that larger projects are built by breaking problems into smaller manageable pieces.

The learner should begin feeling:
- “I can build bigger things.”
- “Large programs are just many small parts working together.”
- “I can organize my ideas.”
- “I can improve and expand projects over time.”

This module should focus more on:
- organization
- decomposition
- planning
- iteration
- debugging strategies

than on introducing major new syntax.

---

# Core Philosophy

This module is not intended to teach formal software engineering.

It should instead teach:
- manageable thinking
- project structure
- iterative building
- confidence with larger codebases

The learner should understand:
“You do not write a giant project all at once.”

---

# Core Concepts

Primary concepts:
- breaking programs into sections
- organizing functions
- reusable systems
- project planning
- debugging larger programs
- separating responsibilities

Secondary reinforcement:
- functions
- loops
- conditionals
- lists
- randomness
- drawing systems

Potential optional concepts:
- lightweight state systems
- menus
- reusable utility functions

Avoid:
- classes/OOP
- formal architecture patterns
- advanced data structures
- design patterns
- package/module systems
- abstract engineering terminology

The focus should remain:
creative and approachable.

---

# Learner Mental Model

Introduce larger projects as:
“Building with smaller blocks.”

Good analogies:
- LEGO builds
- game levels
- rooms in a house
- scenes in a movie

Avoid:
“software architecture” terminology.

---

# Module Structure

Recommended lesson progression:
1. Breaking Problems into Parts
2. Organizing Code into Systems
3. Menus and Navigation
4. Debugging Bigger Programs
5. Expanding Existing Projects
6. Module Project

This module should include more planning support than previous modules.

---

# Lesson 11a — Breaking Problems into Parts

Goal:
Teach decomposition.

Topics:
- identifying repeated behaviors
- separating project sections
- creating functions for major actions

Examples:
```python id="n6a7sl"
def intro():
    pass

def battle():
    pass

def ending():
    pass
````

Activities:

* split a story into scenes
* separate game actions
* organize repeated systems

Practical:
Break an existing project into sections.

---

# Lesson 11b — Organizing Code into Systems

Goal:
Teach grouping related logic together.

Topics:

* helper functions
* reusable logic
* naming functions clearly
* keeping projects readable

Projects:

* inventory systems
* battle systems
* menu systems
* drawing toolkits

Focus:
Programs become easier to understand when organized well.

---

# Lesson 11c — Menus and Navigation

Goal:
Teach larger interactive program flow.

Topics:

* menus
* navigation systems
* choosing actions repeatedly
* lightweight state flow

Examples:

```python id="0c8yej"
print("1. Explore")
print("2. Inventory")
print("3. Quit")
```

Projects:

* game menus
* shop systems
* creature actions
* map navigation

Practical:
Create a multi-screen interactive experience.

---

# Lesson 11d — Debugging Bigger Programs

Goal:
Teach persistence and debugging strategies.

Topics:

* testing one piece at a time
* isolating problems
* reading errors
* using print() for debugging
* incremental development

Educational purpose:
Normalize debugging as part of programming.

This lesson is extremely important psychologically.

The learner should understand:
“Even experienced programmers debug constantly.”

---

# Lesson 11e — Expanding Existing Projects

Goal:
Teach iteration and project growth.

Activities:

* add features to old games
* improve visual projects
* combine previous systems
* refactor repeated logic

Examples:

* add inventory to adventure game
* add weather to simulation
* add random enemies
* add visual maps

This lesson should strongly encourage remixing.

---

# Module 11 Final Project — Build a Larger Multi-System Project

Goal:
Create the learner’s largest project so far using multiple systems together.

Allowed project ideas:

* dungeon crawler
* creature simulator
* sports season simulator
* survival game
* fantasy world
* interactive visual map
* shop and inventory game
* hybrid visual/text experience

Required concepts:

* multiple functions
* collections/lists
* loops
* conditionals
* menus or navigation
* organized structure

Optional:

* randomness
* drawing systems
* animations
* replayability

Validation:
Flexible milestone-based validation only.

Focus on:

* organization
* completeness
* experimentation

not exact solutions.

---

# Project Planning Support

This module should provide lightweight project-planning tools.

Possible prompts:

* What does your project do?
* What screens or scenes does it need?
* What systems are required?
* What functions might help?
* What should happen first?

Potential future feature:
Simple visual project outline board.

Not required for MVP.

# UX Requirements

This module should feel:

* empowering
* creative
* ambitious
* manageable

Strong recommendations:

* collapsible milestone groups
* project map/checklist
* save progress frequently
* clear project organization support

Potential future enhancements:

* file/project explorer

# Hint System Requirements

Hints should increasingly encourage independent reasoning.

Examples:
Instead of:
“Write this exact function.”

Prefer:
“What repeated behavior could become its own function?”

Hints should:

* support planning
* support decomposition
* support debugging strategies

not only syntax.

---

# Error UX Requirements

Common beginner pain points:

* forgetting which function does what
* code organization confusion
* debugging multiple interacting systems
* incomplete logic flow

Error messaging should:

* encourage breaking problems apart
* suggest testing smaller pieces
* reinforce iterative building

Important:
The learner should never feel:
“My project is too big.”

The app should reinforce:
“Build one small piece at a time.”

---

# Sandbox Integration

This module should heavily encourage:

* long-term projects
* iterative expansion
* remixing previous work

Suggested actions:

* “Expand This Project”
* “Add a New System”
* “Turn This Into a Bigger Game”
* “Create a Sequel”

The Sandbox should increasingly feel like:
the learner’s own development space.

---

# Educational Outcome

The learner should finish Module 11 feeling:

* “I can build larger projects.”
* “I can organize complicated ideas.”
* “I can debug and improve my programs.”
* “Large projects are manageable.”

This module should create a major confidence shift from:
“learning coding concepts”
to
“building software projects.”

It should also strongly prepare learners for:

* independent exploration
* future advanced topics
* long-term creative coding interest
