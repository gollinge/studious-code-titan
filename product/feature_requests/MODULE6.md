# Module 6 — Creative Projects I

Module Type:
Project Module

Primary Goal:
Consolidate all concepts from Modules 1–5 through guided but creative project-building.

Educational Purpose:
This module marks the transition from:
“learning programming concepts”
to
“using programming as a creative tool.”

The module should prioritize:
- experimentation
- personalization
- confidence-building
- independent problem solving
- creative ownership

This module should intentionally introduce very little new syntax.

Instead, learners should deepen their understanding of:
- variables
- print()
- input()
- conditionals
- loops
- functions

through larger, more meaningful projects.

---

# Core UX Goals

The learner should feel:
- “I built this.”
- “I can change things and experiment.”
- “I can make games and interactive experiences.”
- “There isn’t only one correct answer.”

The module should feel:
- more open
- less quiz-like
- more creative
- more exploratory

This module should visually and structurally feel different from lesson-heavy modules.

---

# Required UI/CX Pattern

This module uses the reusable Project Studio pattern.

Required screens/components:
- Project Gallery
- Project Brief
- Build Studio
- Milestone Checklist
- Hints Drawer
- Remix Prompts
- Save / Reflection Step

---

# Module Structure

The module should contain:
1. Guided Projects
2. Remix Challenges
3. Open Creation Prompt

Projects should gradually reduce scaffolding.

Project progression:
- Project 1: heavily guided
- Project 2: partially guided
- Project 3: lightly guided
- Final project: mostly independent

---

# Project 1 — Text Adventure

Goal:
Build a branching text-based adventure game.

Concept Reinforcement:
- print()
- variables
- input()
- if / else
- functions

Suggested milestones:
- Create a game intro
- Ask for player name
- Add at least one choice
- Add multiple outcomes
- Create at least one function
- Add replayability or personalization

Suggested remix prompts:
- Make it funny
- Add monsters
- Add treasure
- Add sports theme
- Add pets
- Add magic powers

Validation strategy:
Flexible milestone detection only.

Avoid:
- exact output matching
- line-by-line grading

---

# Project 2 — Quiz Game

Goal:
Build an interactive quiz or trivia game.

Concept Reinforcement:
- variables
- scoring
- conditionals
- functions
- repeated logic

Suggested milestones:
- Ask at least 3 questions
- Track score
- Display final score
- Add win/lose message
- Organize code with functions

Suggested remix prompts:
- Animal trivia
- Sports trivia
- Minecraft trivia
- Silly random trivia
- Custom family quiz

Validation strategy:
Check for:
- input()
- score variable
- conditionals
- multiple questions
- function usage

---

# Project 3 — Pet / Creature Simulator

Goal:
Create a simple interactive creature or pet system.

Concept Reinforcement:
- variables
- state tracking
- functions
- loops
- branching interactions

Suggested milestones:
- Create creature name
- Track at least one stat
- Add actions
- Add changing outcomes
- Create simple interaction loop

Suggested remix prompts:
- Dragon
- Robot
- Dog
- Dinosaur
- Alien creature

Validation strategy:
Flexible milestone detection only.

---

# Final Project — Build Your Own Mini Game

Goal:
Create an original project using any concepts learned so far.

Requirements:
- Use variables
- Use at least one function
- Use at least one conditional
- Include interaction/input
- Include a beginning and ending

Allowed formats:
- game
- simulator
- story
- quiz
- shop
- sports tracker
- anything creative

The learner should be encouraged to:
- remix previous projects
- combine ideas
- personalize heavily

This project should intentionally avoid rigid structure.

---

# Hint System Requirements

Hints should:
- be optional
- progressively reveal information
- encourage problem-solving before showing solutions

Recommended hint levels:
1. Small clue
2. Concept reminder
3. Partial example
4. Full walkthrough

Avoid immediately exposing full answers.

---

# Error UX Requirements

Project modules should normalize debugging.

Error messaging should:
- feel encouraging
- explain problems clearly
- avoid harsh technical wording
- encourage retrying

Examples:
Instead of:
“SyntaxError”

Prefer:
“Python got confused by this line. Check your quotes, spelling, or parentheses.”

---

# Save / Reflection Step

At project completion:
- Allow learner to name their project
- Allow saving locally
- Ask simple reflection prompts:
  - What did you add?
  - What was hardest?
  - What would you improve?

Purpose:
Encourage ownership and iteration.

---

# Sandbox Integration

Every project should include:
- “Continue in Sandbox”
- “Remix this Project”
- “Start from This Template”

Purpose:
Transition learners toward independent experimentation.

---

# Technical Architecture Recommendations

Projects should use:
- milestone-based validation
- flexible completion criteria
- reusable project schemas

Suggested project schema:
- metadata
- concept tags
- milestones
- hints
- remix prompts
- validation rules
- starter templates

Avoid:
- hardcoded exact solutions
- rigid grading systems
- single-solution assumptions

---

# Long-Term Curriculum Role

Creative Projects I serves as:
- the first major consolidation checkpoint
- the transition toward independent creation
- the foundation for all later project-heavy modules

Success criteria are NOT:
- perfect syntax
- perfect structure
- identical solutions

Success criteria ARE:
- experimentation
- persistence
- personalization
- creative engagement
- learner confidence
